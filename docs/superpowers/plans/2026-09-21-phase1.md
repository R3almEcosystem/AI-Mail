# AI-Mail phase 1 remediation plan

Goal: implement the first phase approved after the September 21 audit, against main 0b0a1e21c6349e6ee0df610c9b02bff57d9a513a.

Architecture: browser requests receive operation-level authorization backed by revocable database sessions. Mail adapters share recipient, size, TLS, timeout, and operation-result checks. Demo access is explicit and cannot coexist with live credentials. OAuth navigation preserves callback data until the consent client consumes it.

Constraints: no production data/credential changes, no real mail, no merges. Changes are delivered on a review branch. The database migration must precede promotion and invalidates previous browser sessions. Root src is authoritative; apps/web is retained legacy code, outside the active deployment. MFA policy must fail closed; do not claim enrollment or recovery exists without implementing and testing it.
