# SPIRE — Capability Recovery Engineering & Operator Runbook

**Source:** https://github.com/R3almEcosystem/ASSIST-V2/pull/159 · **Snapshot:** 2026-10-26 · **Status:** proposed, unapproved engineering tasks

This repository implements only the relevant slice of ASSIST's 46-module, 237-epic, 1,422-task program. Original IDs, dependencies and acceptance evidence are canonical in [ASSIST-V2](https://github.com/R3almEcosystem/ASSIST-V2/tree/docs/spire-capability-recovery-20261026/docs/engineering/spire-capability-recovery). This mirror is not a separate task authority.

**Do not enable:** autonomous execution, provider transactions, deployments, partner-regulated operations, production credentials, external publication or changes to Trust Kernel merely because a task is present.

## How to use this runbook

1. Human operator picks one module epic with stated customer value and identifies the source code SHA; inspect current implementation without treating a demo as live.
2. Read corresponding `AST-...` task IDs and dependencies in canonical JSON. Verify source/data rights, legal scope, user/tenant boundaries and an independent reviewer.
3. SPIRE performs inventory, engineering analysis, bounded recommendations and authorized isolated PR/sandbox tests only. Record negative cases, rollback strategy and evidence hashes.
4. Human reviewers accept or reject changes; a separately authorized release operator handles deployment and external effects. SPIRE cannot self-approve or self-merge.
5. Independent postconditions and reproducible tests close the task; a UI checkbox or proposed approval does not constitute completion.

## Release constraints and handoff

Keep production toggles and transaction execution disabled until exact-action, independently audited human approval and end-to-end acceptance exist. Do not interpret any simulated provider, mocked source, demo fixture or unverified email/payment receipt as real operational evidence.

Escalate identity, MFA, custody, financial/regulatory and high-risk actions to the source control architecture MANDATE, Shield, Crucible and Veritas. Record the downstream repository commit/PR with stable task IDs, rather than changing the canonical task ledger.
